## Resumen ejecutivo

Cerramos por completo el flujo de Mi perfil contra Figma. Score promedio de las pantallas auditadas: **96.4/100** (5 sub-componentes auditados, todos en estado Aprobado).

Aprendizajes principales:
1. `flex: 1` en tabs traduce mal `shrink-0` de Figma → causa truncamiento de labels largos. Fix: usar `maxWidth` + ancho natural.
2. `fontStyle: italic` aplicado universalmente a inputs viola Figma — debe ser condicional en estado placeholder (sin valor).
3. Estado de avatar debe vivir en `AuthProvider` para compartirse entre `ProfileScreen` (card) y `UserMenu` (header) — antes vivía como `useState` local y solo se actualizaba en el card.
4. `react-native-svg` captura touches por defecto en Android — `pointerEvents="none"` obligatorio cuando overlay sobre área interactiva.

## Decisiones y trade-offs

1. **Avatar shared state via AuthProvider, no via prop drilling.** El context ya tenía `savedEmail` con SecureStore — replicamos el patrón con `avatarUri`. Alternativa rechazada: lift state al `_layout.tsx` y pasarlo como prop a ProfileScreen + UserMenu (más invasivo).

2. **"Cambiar imagen" link en modal foto: mantenido pese a Figma no mostrarlo.** Decisión del usuario — funcionalidad necesaria; movido a debajo del help text para no competir con el preview.

3. **Iconos Move/Hand en preview: 48px en vez de 56px (Figma).** Compromise por legibilidad en pantallas estrechas.

4. **Pan visual sí, re-crop al guardar no.** Se conecta `PanResponder/Gesture` para que el drag responda visualmente, pero el URI guardado sigue siendo el del cropper nativo. Re-crop con offset queda como M2-FE-04 (necesita `expo-image-manipulator`).

5. **Watermark del fondo aplicado a TODO el tabs layout.** Mismo asset `app-background.png` que usa `AuthScreenShell`. Mejor consistencia visual que aplicar solo en ProfileScreen.
